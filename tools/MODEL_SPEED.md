# Сравнение времени обработки одного PDF

Из корня репозитория, с работающим Docker и приложением:

```powershell
.\.venv\Scripts\python.exe -m tools.compare_model_speed --pdf "E:/RAG/Предметная область 1/dev/D001.pdf" --output runtime/benchmarks/model-speed-NEW
```

Скрипт создаёт четыре новых корпуса с одним и тем же оригинальным PDF, затем
последовательно обрабатывает их через HTTP API приложения. Порядок: GPT-6 Luna,
DeepSeek V4.1 Flash, DeepSeek V4.1 Flash, GPT-6 Luna. Используются точные имена
`openai/gpt-6-luna` и `deepseek/deepseek-v4.1-flash`. Отправляются текст и изображения
страниц, схемы и инструкции остаются одинаковыми. Эталонные таблицы не читаются.

`MODEL_ID` временно меняется для backend и worker через отдельный файл Compose.
`.env` не редактируется; исходная конфигурация восстанавливается в `finally` и
проверяется по API и настройкам worker. Скрипт отказывается перезапускать сервисы,
если есть выполняющиеся задания. Новые запуски используют реальные платные
обращения к ProxyAPI. Ключ берётся из настроек и в отчёты не записывается.

После прерывания используйте ту же команду с `--resume`: сохраняются исходные
Job ID и ключи идемпотентности, повторные оплачиваемые обработки не создаются.
При незавершённом задании скрипт оставляет worker работающим до его завершения,
чтобы не оборвать обработку. Логи worker необходимо собрать до его пересоздания.

Пересчитать отчёт из сохранённых данных, без Docker, API и расходов:

```powershell
.\.venv\Scripts\python.exe -m tools.compare_model_speed --output runtime/benchmarks/model-speed-20261122 --report-only
```

Артефакты:

- `comparison.txt` — читаемый отчёт; `metrics.json` — числа и метаданные вызовов.
- `verification.json` — проверки одинакового приложения и настроек, уникальности
  ответов и отсутствия повторного использования результатов приложения.
- `comparison.json` — порядок запусков, SHA-256 PDF и исходная конфигурация.
- В каждом каталоге запуска: `state.json`, полные ответы в `raw/`,
  `worker_events.json` с точным `elapsed_ms`, `worker_environment.json` с хешами кода.
- `published.json` в каталоге запуска — метаданные загруженного PDF и итоговый
  граф данных. Для дополнения этих файлов без повторной обработки можно запустить
  команду с `--collect-published` вместо `--report-only`.
- `preflight-*.json`, если присутствуют, — отдельные короткие проверки изображения
  и strict JSON; они не входят в четыре обработки и их время.

Worker time считается по событиям `job_item_finished`; при повторах суммируются
интервалы всех попыток. Client time включает очередь и погрешность опроса до 2 с.
Время модели — сумма `elapsed_ms` сохранённых вызовов, включая их сериализацию,
сеть, очередь провайдера, генерацию и внутренние повторы. Перезапуски контейнеров,
загрузка PDF и экспорт в эти времена не входят. Повторное наблюдение после
прерывания может увеличить client time; точное worker time сохраняется в логах.

Кеш ответов приложения не используется, страницы каждый раз готовятся заново.
Автоматический кеш провайдера не отключается; его счётчики остаются в `usage`.
Настройки рассуждений не задаются, поэтому сравниваются значения моделей по
умолчанию, а не выровненный вычислительный бюджет. Два прогона одного документа
не дают статистически надёжного рейтинга. Ошибка, пропуск извлечения или меньший
объём ответа не должны выдаваться за ускорение успешного полного извлечения.
