Замер выполняется из корня `science-extract` при работающем Docker Compose и настроенной модели.
Используются только `dev` и `dev_gold`; каталог `test` не читается.
Логин берётся из `ADMIN_EMAIL`/`ADMIN_PASSWORD` в окружении или `.env` и не попадает в отчёт.

```powershell
.\.venv\Scripts\python.exe -m tools.benchmark --root E:\RAG --output runtime/benchmarks/luna-dev-01 --collect-worker-metrics
```

Команда создаёт два новых корпуса, последовательно обрабатывает все статьи без ручных исправлений,
скачивает таблицы и записывает `metrics.txt`, `metrics.json`, разбор TP/FP/FN и время каждой статьи.
Обращения к модели платные. Эталон копируется для локального сравнения и не передаётся в обработку.
Ошибки и ожидание ручного решения остаются в знаменателе Recall; скрипт не подгоняет результаты под эталон.
Не меняйте код, модель или настройки и не исправляйте созданные корпуса во время замера.

После обычного прерывания добавьте `--resume` с прежним каталогом вывода. Скрипт продолжит наблюдать
существующие задания и не запускает повторно уже законченные, в том числе завершившиеся ошибкой.
После принудительного завершения может остаться `.lock`: удалять его можно только после проверки,
что процесс с записанным внутри PID больше не работает.

Пересчёт сохранённого эксперимента без новых вызовов модели:

```powershell
.\.venv\Scripts\python.exe -m tools.benchmark --output runtime/benchmarks/luna-dev-01 --score-only
```

`--collect-worker-metrics` требует доступа к Docker и добавляет точные сервисные длительности из
событий `job_item_finished.elapsed_ms`, а также идентификатор образа и безопасные настройки worker.
Этот флаг можно добавить и к `--score-only`, чтобы дополнить уже проведённый замер.
Без него время статьи измеряется клиентом и включает очередь и задержку опроса.

Основной строгий scorer сопоставляет строки 1:1 по метрике, точному значению и связанным условиям,
игнорируя произвольные ID. Текстовые описания условий должны совпадать буквально; это консервативная
проектная метрика, а не официальный критерий научной правильности. Отдельная диагностика ищет
совпавшие значения на тех же страницах и игнорирует связанные сущности; её F1 нельзя выдавать за
точность научного извлечения. Все правила и знаменатели записываются в TXT/JSON.
P/R/F1 считаются для `results.csv`; связанные сущности служат контекстом. Количество строк остальных
таблиц не заменяет отдельную оценку правильности всех их полей.

Версия оценщика 1.1 также выводит более широкую диагностику восстановления чисел с явным
словарём обозначений (например, PCE = power conversion efficiency). Она добавлена после
разбора промежуточного солнечного отчёта; исходные две метрики сохранены без изменения.
Эта диагностика игнорирует агрегацию/время/k и связи с сущностями и не является научной
точностью. Полный список разрешённых замен записан в `metrics.json` и исходном Python-коде.

Корректность scorer проверяется тестами `tests/test_quality_metrics.py`. Сравнение эталона с самим
собой допустимо только как проверка оценщика и не является измерением качества модели.

Версия 1.2 исправляет состав оцениваемых Solar-метрик: согласно `submission_template/README.md`
дополнительные показатели вне 11 целевых названий не участвуют в оценке извлечения.
Их названия и количества выводятся в `outside_metric_scope_excluded`; RAG-метрики остаются открытыми.
Это изменение знаменателей, поэтому отчёты разных версий нельзя сравнивать как улучшение модели.
Первоначальный отчёт 1.1 хранится без пересчёта.

Проверка исправлений без нового полного прогона:
`python -m tools.audit_model_outputs --baseline runtime/benchmarks/ИМЯ --output runtime/audit/ИМЯ`.
Скрипт не читает gold и не вызывает модель; проверяет сохранённые ответы и оставшиеся ошибки.
Для адресной проверки этапа исправления на исходных PDF используется
`python -m tools.repair_saved_candidates --baseline runtime/benchmarks/ИМЯ --audit runtime/audit/ИМЯ --output runtime/repair/ИМЯ --max-calls 16`.
Последняя команда разрешает максимум 16 новых вызовов текущей модели из `.env`; ответы сохраняются
и переиспользуются при повторном запуске. По умолчанию `--max-calls=0`, то есть платные вызовы запрещены.
Эта проверка не обновляет БД и не является новым замером точности/успешности всех статей.
